# Website improvement backlog

This list accompanies the [website improvement research](website-improvement-research.md). It balances reliable publishing, reader experience, and maintenance. All 32 items are proposals for later selection. No website behavior has been changed by this research.

**Priority:** P1 means a current correctness or substantial usability issue; P2 means a useful next improvement; P3 means conditional on demonstrated demand. Priority is not a claim of emergency severity. **Effort:** S is roughly half a day to one day, M is two to four days, and L is five to ten days of focused work, including relevant verification. These are preliminary estimates for someone familiar with the repository, excluding editorial content production, account access delays, and translation review.

Confidence is high for reproduced or directly observed defects, medium for implementation risks and usability judgments, and conditional for new capabilities. Each item should ship its acceptance scenario end to end. Where multiple layers are required, keep them in one coherent feature slice. Shared implementation may reduce effort, so estimates should not be summed into a delivery promise.

## Selection guidance

Start with PUB-01, PUB-02, LANG-01, PUB-03, SEO-01, and SEO-02. These address concrete failures or misleading behavior. OPS-01 should support the selected code changes without becoming an independent infrastructure project that delays the customer-visible result. Then address FIND-01 and UX-01/UX-02.

For the next investment, choose between author efficiency (PUB-06) and professional presentation (UX-04) using a real task: either observe Francisco editing an article or ask a prospective collaborator to evaluate a project. PERF-01 and UX-03 are bounded improvements that can proceed without settling the longer-term product direction.

Do not start both CMS options, both search approaches, or a framework migration. Previews should become a separate end-to-end slice only after the author demonstrates a need to inspect the rendered result before publishing. A newsletter, project map, topic collections, before/after slider, and printable portfolio are reasonable future discussion topics, but are intentionally outside this actionable list until their audience and maintenance owner are clear.
